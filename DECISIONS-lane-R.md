| H110 | 2026-10-21 | Online co-op (browser and internet desktop play, LEDGER L-28) goes through a public WebSocket relay, `relay/relay.py`, speaking protocol v1: a text-JSON hello (`host` / `join` + room), relay replies `hosted` / `joined` / `peer_join` / `peer_leave` / `error{code,msg}`, host `kick`, and binary DATA frames with a 5-byte header `[1][target, 0 = all but sender][sender, set by the relay][channel][mode]`. Joiners reach only the host. Room codes are 5 letters from `ACDEFHJKMNPRTWXY`; ids 1 (host) and 2..255. The host-authoritative model (H52) is unchanged; the relay only moves bytes and never logs payloads. | Claude, decided (design given in the lane brief) | Browsers cannot listen and https pages need wss://; ENet across the internet needs port forwarding. A relay is the one shape that serves both; WebRTC would still need signalling and a TURN relay for the same NATs. | current |
| H111 | 2026-10-21 | HHNet gains `host_online()`, `join_online(code)`, `is_relay()`, `room`, `relay_url`, signals `room_ready(code)` and `relay_status(text)`. `make_peer` returns an HHRelayPeer when online and always on the web (there `host()` / `join(address)` mean online, the address being the code). Over the relay JOIN_TIMEOUT starts at `connected_to_server`; `last_error` is the relay peer's sentence; a relay host that loses the relay gets `disconnected()`. The relay URL is `HHRelayConfig.URL` (`wss://hexhunt-relay.onrender.com`, a placeholder until the service exists), overridden by `--relay <url>` or `?relay=<url>` in a browser. | Claude, decided | The transport seam H52 left for Phase 5. Supersedes the browser refusal in H79 (`make_peer` refused on the web). | current |
| H112 | 2026-10-21 | HHRelayPeer (`src/net/relay_peer.gd`) is a MultiplayerPeerExtension over one WebSocketPeer. Its status turns CONNECTED on `hosted` / `joined`, and a joiner emits `peer_connected(1)` only after that. A socket that never opens is retried every 2.5 s, each attempt cut at 12 s, for 90 s, saying "relay asleep, retrying… (N s)"; then "could not reach the relay". Everything is reliable and ordered over TCP whatever transfer mode HHNet asks; the mode byte still travels. | Claude, decided | SceneMultiplayer answers peer_connected(1) with connected_to_server, HHNet sends HELLO from there, and send_bytes refuses unless the peer already reads CONNECTED. Measured: Godot's WebSocketPeer to a refused local port stays CONNECTING for 30 s (there is no handshake timeout property in 4.7), so the peer cuts attempts itself. A Render free instance takes about a minute to wake. | current |
| H113 | 2026-10-21 | Relay limits: 5 peers per room, 256 KB frames, 200 rooms, 1000 connections, 10 s hello timeout, 15 min idle per ROOM (no data frame from anyone), token buckets per connection of 300 frames/s (burst 900) and 256 KB/s (burst 1 MB), a 512-frame send queue per receiver (overflow drops that peer as `slow`), no permessage-deflate. GET without Upgrade answers 200. Binds 0.0.0.0:$PORT when PORT is set (Render), else 127.0.0.1:8765. Hosted as a Render Blueprint free web service (`render.yaml`, rootDir relay); click-steps in `relay/README.md`. | Claude, decided | The idle timeout is per room, not per connection: a guest who only watches the stream sends nothing for long stretches and must not be cut while the room is busy. Four hunters measured at about 65 frames/s and 34 KB/s from the host, well inside the buckets. | current |
| H114 | 2026-10-21 | Lobby "Play together" has a LAN / Online switch over the same two rows (the web build is Online only and hides the switch). Boot: `--host --online`, `--join-code <code>`, `--relay <url>`; with `--autoplay` the lobby prints its notes (`[lobby] Room XXXXX is open`) so a script can read the code. | Claude, decided | Lane brief. | H115 | 2026-10-21 | On an error the relay sends `error{code,msg}`, waits 1 s and only then closes (reason = the code).
