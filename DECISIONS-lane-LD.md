# DECISIONS, lane LD (load times): H460-H469

Rows in DECISIONS.md's format, for the integrator to fold in.

| # | Date | Decision | By | Why | Status |
|---|------|----------|----|-----|--------|
| H460 | 2026-10-22 | **Boot preload.** At game open, before the first screen, HHPreload (`src/game/preload.gd`) pays the first-load cost once behind the loading screen: (1) every model, texture, music track and sound under `res://art` and `res://audio` loads into `HHPreload.cache`, kept alive for the run; (2) the region map is built in front of its camera; (3-6) each monster is built as a real solo NORMAL fight in its own arena (lance / daggers / bow / lance, element pairs fire-water, ice-thunder, wind-dark, light-fire, so every arena, monster, weapon and element is drawn), its own HHWarmup runs, then the camera turns to the monster for `preload_frames` frames while the sim steps (the NORMAL tier effects appear) and a mesh-proxy pass (H462) follows; (7) the ambush, scrubbed to the burst. Each step is freed after; the Master bus is muted while it runs. The per-fight warm-up (H432) stays as the fallback. Knobs: `preload_on_web` 1, `preload_on_desktop` 0, `preload_frames` 6; `--preload` / `--no-preload` force it. Headless runs, the self-test and `--shot` captures never preload. | Author (want), Claude, decided (how) | "Once we got over the load times coop was seamless. Maybe bake in the load times before you enter lobby? The best thing that worked for us was to 'go hunting', wait for the 5m load time. Then we were able to enter ambush." Building the real scenes covers StandardMaterial3D variants, skinned meshes, lights and the arena's own shaders, which a shader list alone misses. | current |
| H461 | 2026-10-22 | **The tier effects share their shaders.** HHTierFx built three Shaders from code per instance, so every NORMAL fight compiled them again on the first tell (the H432 gap). They are now static and shared (`HHTierFx.shared_shader`, `warm_shaders()`), so the preload and every fight's HHWarmup compile the objects the effects draw with. | Claude, decided | A new Shader object is a new compile; a shared one is compiled once per run. | current |
| H462 | 2026-10-22 | **HHWarmup covers more.** Its shader list is every `.gdshader` under `res://shaders` and `res://src` (the arena's `gk_fade` was missed) plus the tier shaders; the `*_web` variants are skipped on Forward+ (they warned about missing globals there) and the web globals are declared before they compile in the browser. `add_proxies(root, hidden_only)` draws a tiny copy of every distinct mesh + material under a node in front of the camera: the boot preload does it for everything in each step (props behind the camera, the unseen half of the map), a fight's own warm-up for its hidden nodes only (pooled effects, a hidden monster). | Claude, decided | A pipeline compiles on first draw; a hidden or off-screen node is never drawn until it matters. | current |
| H463 | 2026-10-22 | **A progress read.** The loading screen says "Preparing the hunt... 3/7" over the step's line ("Waking Swampfang in the Lilypad Pond"; the resource step adds a file count) and shows a thin gold bar under it, so a player can tell it has not frozen. The line is painted two frames before each step's long frame. | Author (want), Claude (look) | "a long load screen would be okay" (H432), but a silent one reads as a hang. | current |
| H464 | 2026-10-22 | **The desktop skips the preload by default.** Measured on the dev machine (RX 9070): Forward+, with the driver's pipeline cache warm, a first Colambros fight took 1437 ms to build + 216 ms to warm without the preload, 773 + 112 ms after a 9.5 s preload; truly cold (first run ever) it was 2454 + 4898 ms. The Compatibility renderer on the desktop (the closest local stand-in for the browser): 1027 + 8002 ms without, 683 + 374 ms after a 25.5 s preload. Nine seconds up front to save under one is a bad trade on Forward+, so `preload_on_desktop` is 0; F1 or `--preload` turns it on. The browser was not measured here. | Claude, decided | "Desktop should stay fast." | current |
| H465 | 2026-10-22 | A windowed fight prints `fight: built in N ms, warm and ready M ms later` when its loading screen closes, and the preload prints each step's time, so a load can be measured without a profiler (the browser console shows the same lines). | Claude, decided | Numbers, not impressions, for the next browser test. | current |
| H466 | 2026-10-22 | **Not covered.** Each fight still builds its arena (procedural geometry, about 0.7-1.1 s on the desktop) on entry; the lobby (2D), the results screen and the F1 panel are not preloaded; a mesh proxy is drawn unskinned, so skinned pipelines come only from the real bodies in view (the hunter, and the monster the camera turns to); a material made fresh during play with a shader or flag combination nothing drew at load still compiles then. The browser numbers are unmeasured until the author plays. | Claude, decided | Logged so the next freeze report can be checked against this list. | current |
