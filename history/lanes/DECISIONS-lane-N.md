## Requests

- **R-N1 (Lane C, `src/game/fight.gd`): the fight-facing API is 3 calls plus one signal.** Exact lines:
  ```gdscript
  var rep: HHReplicator = null                       # new member

  # setup_cfg(), after setup(...) has built every cfg.players hunter and set player_id = cfg.local_id:
  rep = HHReplicator.attach(self, sim, cfg)          # null when cfg.net is "solo" (or missing); client: clears brains/hooks
  if rep != null and rep.role == "client":
      rep.snapshot_applied.connect(_on_net_events)
      rep.lost.connect(func(): _finish("abort"))     # the host left (or Lane C's own "host_lost" result)

  # _process(): a client never steps; the host merges and publishes
  if rep == null or rep.role == "host":
      while _acc >= HHSim.TICK and steps < 6:
          _acc -= HHSim.TICK
          var ev := sim.step(rep.merge(_pending) if rep != null else _pending)
          _pending = {}
          if rep != null:
              rep.publish(sim.tick, ev)              # every tick, right after step
          for e in ev:
              _feed(e)                               # today's body: _note(e); view.on_event(e, sim); sfx.on_event(e, sim)
          steps += 1

  func _on_net_events(events: Array) -> void:        # client: the host's events for each tick the mirror took
      for e in events:
          _feed(e)

  # _order(o): a client sends instead of queueing
  if rep != null and rep.role == "client":
      rep.send_order(o)
      return
  ```
  The replicator pumps itself in its own `_process` (it is the fight's child). Autoplay must stay off on a client. On a client `sim.tick` advances in jumps when it catches up; `_watch_over` works unchanged (it reads `sim.over`, which replicates).
- **R-N2 (Lane C / integrator, `src/game/shell.gd`):** the shell owns the connection for the whole session: in `HHShell._ready()` (or `_init`) `var net := HHNet.new(); net.name = "Net"; add_child(net)`. `show_screen` frees screens only, so Net (and `Net/Session`) survive lobby -> fight -> lobby. `HHReplicator.attach` finds it with `HHNet.find(fight)`.
- **R-N3 (Lane C, lobby):** Host -> `net.host()`; Join -> `net.join(address)` then wait for `connected` / `failed` (show `net.last_error`, it is a sentence); party list from `net.session.joined` + `net.session.members` (redraw on `session.changed`); own picks and ready -> `session.set_mine({ weapon, element, backup, upgrades, ready, name })`; host tiles -> `session.host_set({ arena, monster, seed })` (clients show them read-only from `session.fields`); Start (host) -> `session.start()` (returns ERR_UNAVAILABLE until all ready); every peer: `session.start_fight.connect(func(cfg): shell.play(cfg))`; when the fight screen finishes, `net.session.end_fight()` so the host takes joiners again. Leave -> `net.leave()`.
- **R-N4 (Lane S, sim):** keep every new piece of co-op state INSIDE the unit dictionaries (e.g. `u.downed`, `u.revive_ticks`, `u.revive_by`, a threat entry) or in `telegraphs` / `projectiles` / `charge.entries`. Those replicate with no change to HHSnapshot. A new top-level sim field (say `sim.revives = {}` or a threat table on `sim`) does not reach clients until it is added to `HHSnapshot.capture/apply/delta`: tell Lane N or the integrator. Same for anything a view reads from a brain object instead of the unit: brains do not exist on a client.
- **R-N5 (integrator, guide/02):** fold the names that grew past the contract: HHNet `send`, `send_encoded`, `peers()`, `is_client()`, `poll()`, `session`, `player_name`, `accepting` / `refuse_reason`, `last_error`, `names`, `stats` / `sent_rate`, signal `message`, `make_peer(server, address, port, peers)`; HHSession `joined`, `fields`, `unit_id(peer)`, `build_cfg(peer)`, `end_fight()`, `start(force)` -> Error; HHSnapshot `same`, `encode` / `decode`, `age_charge`, `clean`; HHReplicator `attach(fight, sim, cfg)`, `merge(local)`, `role`, `stats`, `request_full()`, `pump()`, signal `lost`.
- **R-N6 (integrator, `src/core/sim.gd`, optional):** `state_hash` does not include `facing`, `statuses`, `cooldowns`, `windup` or telegraph hexes, so it is a good but partial desync detector. The tests also compare whole captures (`HHSnapshot.same`), which is exact; a wider hash would make the live `mismatches` counter exact too. Not needed for Phase 4.
